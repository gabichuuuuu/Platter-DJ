# GitHub setup

Settings of the repository on GitHub. They are applied by the maintainer by hand; nothing in this
repository applies them. The repository `Platter-DJ` lives in the personal account of the
maintainer, on the free plan, and is public.

## Current settings

- **Visibility:** public. Before it changed, `cargo xtask privacy` and `cargo xtask cleanroom`
  passed on a full clone with the heads of every pull request, because the whole history is
  visible.
- **Pull requests:** anyone can create one; only the maintainer merges, after review
  (`docs/decisions/0018-pull-requests-open-to-everyone.md`).
- **Merging:** squash merging only; automatically delete head branches.
- **Actions:** default workflow permissions read-only. `ci.yml` runs Linux, Windows and macOS on
  every run of a public repository; the condition on `github.event.repository.private` only
  limits a private copy.
- **Rule of `main`:** branch protection, applied to administrators too: changes through pull
  requests only; the `gate` checks of the three systems required; no force pushes and no
  deletion; linear history; 0 approvals while there is a single maintainer.
- **Security:** Dependabot alerts and Dependabot security updates.
- **CodeRabbit:** application installed.

## Still to apply

In this order:

1. Security: secret scanning with push protection, and private vulnerability reporting, which
   `SECURITY.md` asks reporters to use.
2. Actions: require approval to run workflows for pull requests from outside collaborators, so
   no workflow runs on outside code before the maintainer looks at it.
3. Settings > Moderation options > Interaction limits > Pull request limits: limit the open pull
   requests per user without write access (value decided by the maintainer;
   <https://github.blog/changelog/2026-06-17-limit-open-pull-requests-for-users-without-write-access/>).
4. Discussions, with categories for questions, ideas and controllers.
5. GitHub Pages: Settings > Pages > Source "GitHub Actions". `.github/workflows/pages.yml`
   then publishes the progress page generated by `cargo xtask parity --site`; until the source
   is set, its deploy job fails.
6. With more than one maintainer, require at least one approval in the rule of `main`.

## Files in this repository that GitHub reads

| File | Purpose |
| --- | --- |
| `.github/workflows/ci.yml` | The gate, `cargo xtask ci`, on each system |
| `.github/workflows/pages.yml` | Progress page, published once the repository is public |
| `.github/workflows/pr-quality.yml` | Quality filter for pull requests from outside the project |
| `.github/dependabot.yml` | Weekly updates of cargo dependencies and of the pinned actions |
| `.github/pull_request_template.md` | Checklist of a pull request |
| `.github/ISSUE_TEMPLATE/` | Forms for bugs, features and controller reports |
| `.coderabbit.yaml` | Automatic review, skipping Dependabot |

Actions are pinned by commit SHA with the version in a comment. A SHA is obtained with
`git ls-remote --tags https://github.com/<owner>/<repo>` and never written from memory;
Dependabot keeps them current.
